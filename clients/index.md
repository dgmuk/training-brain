## 🆔 Принципы идентификации

### client_id (slug)

Каждый клиент имеет уникальный **client_id**, это slug на латинице, по нему называется папка `clients/<client_id>/` и проставляется в YAML frontmatter всех файлов клиента.

Правила формирования:

1. Только латиница в нижнем регистре, цифры и дефис.
2. Имя клиента транслитерируется по принципу читаемости (Дмитрий → `dmitry`, Александр Попов → `aleksandr-popov`, Ольга Иванова → `olga-ivanova`).
3. Если slug уже занят, добавляется фамилия или цифровой суффикс (`aleksandr-popov-2`).
4. Slug фиксируется на старте и **не меняется никогда**, даже если клиент сменил фамилию.

### Имя в работе

Это короткое имя, которое тренер использует в разговоре («Димон», «Александр», «Оля Питер»). Может совпадать с обычным именем или быть прозвищем. Используется для поиска по неполным данным от тренера.

### Полное имя

Имя и фамилия как в анкете. Используется в профиле и официальных документах клиенту.

## 🔍 Алгоритм поиска клиента

Когда тренер присылает дневник или сообщение без явного указания клиента, действуй по шагам:

```
1. ПРОВЕРИТЬ YAML FRONTMATTER в самом дневнике
   → если есть client_id, mesocycle, week, использовать сразу

2. ПРОВЕРИТЬ ИМЯ В ТЕКСТЕ ДНЕВНИКА
   → искать строку «Клиент: ...» или подпись внизу
   → сопоставить с колонкой «Имя в работе» или «Полное имя» в этом реестре

3. ПРОВЕРИТЬ КОНТЕКСТ ЧАТА
   → последний клиент, упомянутый в этом разговоре, наиболее вероятен
   → но если в дневнике другой client_id, доверять YAML

4. ЕСЛИ КЛИЕНТ НЕ ОПРЕДЕЛЁН ОДНОЗНАЧНО
   → НЕ создавать week-(N+1).md
   → ответить тренеру списком похожих клиентов из реестра
   → попросить уточнить client_id

5. ЕСЛИ В РЕЕСТРЕ НЕТ ПОДХОДЯЩЕГО КЛИЕНТА
   → возможно это анкета нового клиента (Схема А), а не дневник
   → перечитать сообщение на предмет анкеты
   → если это всё-таки дневник от неизвестного клиента, спросить тренера
```

## 📌 Какой именно дневник от какого мезоцикла

После определения `client_id` идёт второй уровень идентификации, **какая именно неделя**.

Алгоритм:

```
1. Прочитать YAML frontmatter дневника
   → mesocycle: 1, week: 2 (точное соответствие)

2. Если YAML нет, искать в тексте
   → заголовок «# Неделя N» даёт N
   → блок «**Период:** YYYY-MM-DD — YYYY-MM-DD» даёт диапазон дат

3. Открыть в папке клиента mesocycle-N/overview.md
   → сверить план мезоцикла со статусами недель
   → найти неделю со статусом 🔄 «Активна» или ⏳ «Ожидает»
   → её номер должен совпасть с N из дневника

4. Если расхождение, например пришёл дневник недели 2, а активна неделя 4
   → это либо ошибка тренера, либо клиент пропустил несколько недель
   → не создавать программу автоматически, спросить тренера
```

## 🆕 Когда добавлять клиента в реестр

Сразу после Схемы А (создание полной папки нового клиента) добавить строку в таблицу выше. Заполнить все колонки, поставить статус 🟢 + текущая мезо/неделя.

При смене статуса (закончил мезо, пропал на месяц, ушёл из системы) обновить колонку Статус.

### Возможные статусы

| Иконка | Значение |
|--------|----------|
| 🟢 | Активен, регулярно присылает дневники |
| 🟡 | На паузе, не присылает дневник 2+ недели |
| 🔴 | Внеплановый делоад / травма / пересборка плана |
| ⚫ | Архив (закончил работу) |

## 🔄 Ротация изоляции (обязательно для Схемы Б)

При **еженедельной прогрессии** модель смотрит блок **«Ротация изоляции A/B»** в `mesocycle-N/overview.md` активного мезоцикла:

| Ситуация | Что в overview |
|----------|----------------|
| Мезо 2+ (средний клиент, гипертрофия) | Режим `default`, таблица слотов A/B, календарь недель |
| Мезо 1 (новичок, перерыв, калибровка) | Режим `off`, изоляция фиксирована до мезо 2 |
| Просьба клиента / указание тренера | Слот `fixed` или режим `off`/`fixed` целиком |
| Силовой блок, специализация на жиме | Часто `off` или минимум слотов |

Без таблицы в overview изоляция **не чередуется** автоматически. Подробно: [[../knowledge-base/methodology/isolation-rotation]]

## 📂 Структура папки клиента

Полный канон, legacy-раскладки и чеклист миграции: **[[STRUCTURE]]**.

```
clients/<client_id>/
├── README.md
├── questionnaire-raw.md
├── profile.md
├── macrocycle/
│   ├── overview.md
│   ├── strategy.md
│   └── progress-log.md
└── mesocycle-N/
    ├── overview.md              ← + ротация A/B
    ├── week-N.md                ← continuous week number
    └── week-N-filled.md         ← опционально
```

## 🔁 Архивация клиентов

Если клиент уходит, не удаляй папку, а:

1. Меняй статус в реестре на ⚫ Архив.
2. Перенеси строку в раздел «Архив клиентов» (создаётся ниже).
3. Папку оставляй на месте, она может понадобиться при возврате клиента (при возврате client_id переиспользуется).
