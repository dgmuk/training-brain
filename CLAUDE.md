## 🔴 ВЫСШИЙ ПРИОРИТЕТ — ДВА ПРАВИЛА, ВАЖНЕЕ ВСЕХ ОСТАЛЬНЫХ

### 🔴 ПРАВИЛО №1. Стиль речи без длинных тире

В любых ответах в чат, в любых текстах рекомендаций (в `week-N.md`, `mesocycle-overview.md`, `macrocycle/overview.md`, в комментариях клиенту, в чек-инах и в общении с тренером) запрещено использовать длинное тире (символ `—`, U+2014) как разделитель частей предложения.

Запрещён стиль вида:
- «Сегодня подбор весов. Каждое упражнение начинай с лёгкого подходящего, корректируй по факту. Ориентир — RIR 3-4 в последнем подходе. Если техника плывёт — снижай вес сразу.»

Вместо длинного тире используй запятые, союзы (потому что, чтобы, если, и, но), двоеточие, или раздели мысль на два предложения. Предпочтение отдаётся длинным предложениям через запятую, в стиле живой русской речи.

Правильно:
- «Сегодня подбор весов, каждое упражнение начинай с лёгкого подходящего и корректируй по факту, ориентир по RIR 3-4 в последнем подходе, если техника плывёт сразу снижай вес.»

Где разрешено длинное тире:
- В диапазонах чисел и дат: `2026-05-14 — 2026-05-21`, `MEV+2 → MEV+2`, формат периода в шапке `week-N.md`.
- В таблицах как разделитель ячеек или прочерк.
- В заголовках разделов внутри `knowledge-base/` если это исторически устоявшийся научный текст (но новые тексты пиши без тире).

Это правило приоритетнее всех остальных стилевых норм. Если возникает конфликт между лаконичностью и этим правилом, выигрывает это правило.

### 🔴 ПРАВИЛО №2. Имена упражнений и видео-ссылки только из библиотеки

Единственный источник правды для названий упражнений и ссылок на YouTube видео это файл [[knowledge-base/exercises/exercise-library]].

Правила:
1. При составлении любой `week-N.md` бери имя упражнения из библиотеки буква-в-букву, регистр и пунктуация должны совпадать.
2. Ссылку `[Видео](url)` подставляй только ту, которая указана в библиотеке для этого упражнения, не выдумывай ссылки.
3. Если в библиотеке для упражнения стоит плейсхолдер `https://...` или ссылки нет, не вставляй строку `[Видео](...)` в `week-N.md`, оставь только заголовок упражнения и строку подходов, и сообщи тренеру о пропуске в библиотеке отдельным предложением в ответе.
4. Если нужного упражнения в библиотеке нет вообще, не добавляй его в программу самостоятельно, выбери ближайшую альтернативу из библиотеки и предупреди тренера, либо попроси добавить упражнение в библиотеку перед публикацией недели.
5. При добавлении нового упражнения в библиотеку соблюдай формат блока, описанный в самой библиотеке.

Это правило обязательно для любых файлов программ (`week-N.md`, шаблоны мезоциклов, готовые программы). В обычной переписке с тренером можно упоминать упражнения свободнее.

## 🌐 ИНТЕГРАЦИЯ С METASYSTEM — единый круг работы

> Этот репозиторий не одинокий, он связан с приложением клиента MetaSystem через GitHub API. Файлы здесь не лежат «на полке», они активно читаются и пишутся MetaSystem'ом по контракту описанному ниже. Любая модель должна понимать этот контракт, иначе цикл сломается.

### Архитектура связки

```
┌────────────────────────┐                    ┌─────────────────────────┐
│  Claude в IDE          │                    │  Клиент в приложении    │
│  (этот репозиторий)    │                    │  (MetaSystem)           │
│                        │                    │                         │
│  1. Создаёт план       │                    │  3. Тренируется         │
│     week-N.md          │                    │     заполняет факт      │
│                        │                    │                         │
│  6. Анализирует        │                    │  4. Жмёт «Завершить     │
│     week-N-filled.md   │                    │     неделю»             │
│                        │                    │                         │
│  7. Пишет week-(N+1)   │                    │                         │
└──────────┬─────────────┘                    └──────────┬──────────────┘
           │                                              │
           │ git push (плагин Obsidian)                   │ GitHub API
           │                                              │ (PUSH дневника)
           ▼                                              │
    ┌──────────────────────────────────────────────────┐ │
    │  GitHub репозиторий dgmuk/training-brain         │ │
    │  (источник правды, облако)                       │ │
    │                                                  │ │
    │  clients/<slug>/mesocycle-N/                     │ │
    │    ├── week-1.md         ← план от Claude        │◄┘
    │    ├── week-1-filled.md  ← дневник от MetaSystem │ ◄── PUSH
    │    ├── week-2.md         ← план от Claude        │
    │    └── ...                                       │
    └────────────────┬─────────────────────────────────┘
                     │
                     │ MetaSystem GET (импорт недели)
                     ▼
              ┌──────────────────┐
              │  MetaSystem      │
              │  (Next.js)       │
              │  показывает план │
              │  клиенту в UI    │
              └──────────────────┘
```

### Полный цикл работы с одним клиентом за один микроцикл

1. **Создание клиента (Схема А).** Тренер открывает чат с Claude в IDE, скидывает анкету. Claude создаёт всю папку клиента, включая `mesocycle-1/week-1.md` (обычно калибровочная). Файлы коммитятся в репо плагином Obsidian.
2. **Загрузка недели в приложение клиента.** Тренер заходит в админку MetaSystem → карточка клиента → жмёт «Загрузить неделю из training-brain». MetaSystem через GitHub API находит свежую `week-N.md` в `clients/<slug>/mesocycle-M/` и показывает форму загрузки с предзаполненным markdown.
3. **Тренировки.** Клиент в приложении видит план, выполняет упражнения, заполняет факт подходов и заметки самочувствия. На последнем дне недели заполняет форму чек-ина (вопросы парсятся из блока `## 📊 Чек-ин в конце недели` плана).
4. **Экспорт дневника обратно в репо.** В админке тренер жмёт «В training-brain» рядом с программой клиента. MetaSystem собирает заполненный markdown по формату [[templates/week-diary-input]] и пушит файл `week-N-filled.md` рядом с исходным `week-N.md` (одна папка, тот же мезоцикл) прямо в `main` через GitHub API.
5. **Прогрессия (Схема Б).** Тренер открывает IDE с этим репозиторием. Перед сессией обновляет локальную копию (`git pull` или авто-pull плагина Obsidian) — подтягивается свежий `week-N-filled.md`. Пишет Claude фразу типа «Дима сдал неделю N». Claude по правилам Схемы Б находит файл, разбирает, генерирует `week-(N+1).md`. Цикл возвращается к шагу 2.

### Конвенция имён файлов

В одной папке `clients/<slug>/mesocycle-N/` для каждой недели N лежат два файла:

| Файл | Кто пишет | Что внутри |
|------|-----------|------------|
| `week-N.md` | Claude (этот репо) | План недели от тренера. Никакого факта нет. |
| `week-N-filled.md` | MetaSystem (через GitHub API) | Тот же план + фактические подходы клиента + чек-ин в конце недели. |

Эта конвенция формализована [[templates/week-diary-input]] и выполняется автоматически. Когда Claude генерирует `week-(N+1).md`, он:
- Читает план `week-N.md` для контекста (что было запланировано).
- Читает `week-N-filled.md` для факта (что сделано).
- Пишет новый `week-(N+1).md` (план следующей недели).

`week-N.md` после публикации не меняется. `week-N-filled.md` пишется один раз когда клиент завершает неделю и больше не перезаписывается без явного запроса тренера.

### Правила работы с frontmatter

YAML frontmatter в начале каждого файла критичен (см. [[#🆔 ИДЕНТИФИКАЦИЯ КЛИЕНТОВ]]). MetaSystem при экспорте дневника **сохраняет frontmatter из исходного `week-N.md` байт в байт**, без модификаций. Если frontmatter в исходнике отсутствовал, MetaSystem собирает свежий из метаданных программы (slug клиента из карточки, week, period, type=standard). Это значит:

- Когда Claude создаёт `week-N.md`, frontmatter обязателен и валиден. Тогда `week-N-filled.md` будет иметь идентичный frontmatter и идентификация клиента однозначная.
- При генерации `week-(N+1).md` Claude копирует frontmatter из `week-N.md`, инкрементируя `week` и пересчитывая даты `period_start/period_end`.

### Сторона MetaSystem (что нужно знать модели)

- MetaSystem не лезет в `knowledge-base/`, `templates/`, `macrocycle/`, `profile.md`, `clients/index.md`. Эти файлы — исключительно зона тренера и Claude.
- MetaSystem читает только `clients/<slug>/mesocycle-N/week-N.md` для загрузки клиенту.
- MetaSystem пишет только `clients/<slug>/mesocycle-N/week-N-filled.md` после завершения клиентом недели.
- MetaSystem кеширует `knowledge-base/exercises/exercise-library.md` для проверки имён упражнений в админке (валидирует что Claude не выдумал упражнение, и подставляет недостающие ссылки на видео).
- MetaSystem не редактирует план, только создаёт `-filled` версию.

Если файла `week-N.md` нет, MetaSystem ничего не загрузит и попросит тренера создать его в Obsidian. Если slug клиента не задан в карточке MetaSystem, кнопки импорта/экспорта будут заблокированы.

## 🆔 ИДЕНТИФИКАЦИЯ КЛИЕНТОВ — для масштаба 40+

> Когда клиентов становится много, без чёткой идентификации система сломается. Этот раздел задаёт три уровня идентификации, которыми пользуется любая модель в любой сессии.

### Три уровня идентификации

**Уровень 1. YAML frontmatter в файле week-N.md (главный)**

Каждый план и дневник содержит блок в самом начале файла:

```yaml
---
client_id: dimon
client_name: Дмитрий
mesocycle: 1
week: 1
period_start: 2026-05-11
period_end: 2026-05-17
type: standard
---
```

Если frontmatter есть, идентификация однозначная, ничего больше искать не нужно.

**Уровень 2. Имя файла и путь**

`clients/dimon/mesocycle-1/week-1.md` уже содержит client_id и mesocycle/week. Если frontmatter повреждён, используется путь.

**Уровень 3. Текст и контекст чата**

Только если первые два уровня не дают ответа. Используются: подпись «Клиент: ...» в дневнике, последний клиент в текущем чате, диапазон дат `period_start/period_end` для сужения поиска.

### Реестр клиентов

Все клиенты с их `client_id`, текущим статусом и активными мезо/неделями зарегистрированы в [[clients/index]]. Это единственный источник правды для определения «есть ли такой клиент».

При создании нового клиента (Схема А) обязательное действие, добавить строку в этот реестр. Без записи в реестре клиент в системе не существует.

### Алгоритм идентификации при еженедельной прогрессии

```
ШАГ 1. Прочитать YAML frontmatter входящего дневника
   → если есть client_id, mesocycle, week
   → перейти к ШАГ 5 (создание следующей недели)

ШАГ 2. Если frontmatter нет, извлечь из содержимого
   → заголовок «# Неделя N» даёт N
   → блок «**Период:** YYYY-MM-DD — YYYY-MM-DD» даёт диапазон дат
   → подпись/упоминание клиента в тексте
   → перейти к ШАГ 3

ШАГ 3. Сопоставить с реестром clients/index.md
   → найти клиента по имени или периоду активного мезо
   → если совпадение однозначное, перейти к ШАГ 5
   → если несколько кандидатов или ноль, перейти к ШАГ 4

ШАГ 4. Спросить тренера
   → перечислить кандидатов из реестра с их client_id
   → попросить уточнить
   → НЕ создавать week-(N+1).md до уточнения

ШАГ 5. Открыть mesocycle-N/overview.md клиента
   → проверить что week из дневника совпадает с активной неделей
   → если расхождение, спросить тренера до создания

ШАГ 6. Создать week-(N+1).md в нужной папке клиента
   → обязательно с YAML frontmatter
   → client_id, client_name, mesocycle, week+1, новые даты, type
```

### Правила создания client_id (slug)

При первом касании с клиентом (Схема А) формирую client_id по правилам:

1. Только латиница в нижнем регистре, цифры и дефис.
2. Транслитерация по читаемости: Дмитрий → `dmitry`, Александр Попов → `aleksandr-popov`, Ольга Иванова → `olga-ivanova`.
3. Если slug уже занят в реестре, добавить фамилию или цифровой суффикс (`aleksandr-popov-2`).
4. Slug фиксируется на старте и не меняется никогда.

После создания клиента сообщи тренеру `client_id` отдельной фразой. Этот же slug тренер вписывает в карточку клиента в MetaSystem (поле «client_id training-brain») один раз — после этого MetaSystem умеет находить папку клиента в репозитории.

### Что должно быть во frontmatter

Поля и их назначение:

| Поле | Обязательно | Назначение |
|------|-------------|------------|
| `client_id` | да | Slug, по нему находится папка |
| `client_name` | да | Читаемое имя для контекста |
| `mesocycle` | да | Номер мезоцикла |
| `week` | да | Номер недели в мезоцикле |
| `period_start` | да | Дата начала недели, ISO YYYY-MM-DD |
| `period_end` | да | Дата конца недели, ISO YYYY-MM-DD |
| `type` | да | `standard` / `calibration` / `deload` |

Этот frontmatter **обязателен в каждом week-N.md**, в шаблонах он уже есть как заготовка.

### Применимость по сценариям

- При создании нового клиента (Схема А), frontmatter заполняется на основе анкеты.
- При еженедельной прогрессии (Схема Б), frontmatter копируется из предыдущей недели с инкрементом `week` и пересчётом дат.
- Когда MetaSystem пишет `week-N-filled.md`, frontmatter переносится из `week-N.md` без модификаций. Если в исходном `week-N.md` frontmatter отсутствовал, MetaSystem создаёт его из метаданных программы. В обоих случаях для идентификации можно полагаться на frontmatter в `-filled.md`.

## 🔁 ПРОТОКОЛ ВЗАИМОДЕЙСТВИЯ — две схемы работы

> Это операционный контракт между тренером и моделью. Любая модель в любой сессии должна работать по этим схемам автоматически, без уточняющих вопросов, если входные данные соответствуют формату.

### СХЕМА А. ПЕРВОЕ КАСАНИЕ С КЛИЕНТОМ

**Триггер:** тренер прислал заполненную анкету нового клиента (формат [[templates/client-questionnaire]]) или текст в свободной форме с этими полями.

**Действие:** сразу создать полную папку клиента целиком, без уточняющих вопросов, чтобы у тренера была вся картина.

**Что создаём за один проход:**

```
clients/<имя-латиницей>/
├── README.md                        ← навигация
├── questionnaire-raw.md             ← оригинальная анкета без редактуры
├── profile.md                       ← обработанный профиль с расчётами MEV/MAV/MRV
├── macrocycle/
│   ├── overview.md                  ← 6-месячный план (5-6 мезо)
│   └── strategy.md                  ← обоснование выбора моделей и сплита
└── mesocycle-1/
    ├── overview.md                  ← план мезоцикла для тренера
    └── week-1.md                    ← калибровочная неделя в формате парсера
```

**Алгоритм за один проход:**

1. Прочитать анкету, валидировать данные на правдоподобность и противоречия.
2. **Сформировать `client_id`** по правилам из раздела «🆔 ИДЕНТИФИКАЦИЯ КЛИЕНТОВ» (slug на латинице).
3. **Проверить уникальность `client_id`** в [[clients/index]], если занят, добавить суффикс.
4. Проверить медицинский допуск по [[knowledge-base/contraindications/medical-clearance]], если красный свет, остановиться и сообщить тренеру до создания файлов.
5. Создать папку `clients/<client_id>/` и все 6 файлов выше.
6. Объективно оценить уровень клиента по силовым в анкете, не доверять самооценке.
7. Рассчитать персональные MEV/MAV/MRV по [[knowledge-base/methodology/mrv-personalization]] и внести в profile.md.
8. Выбрать сплит по [[knowledge-base/methodology/split-selection]] и обосновать в strategy.md.
9. Выбрать модель периодизации по [[knowledge-base/periodization/models]].
10. Распланировать макроцикл на 6 месяцев в `macrocycle/overview.md` (5-6 мезо с прогрессией MEV+2 между ними).
11. Создать `mesocycle-1/overview.md` с планом 5 недель, объёмом и упражнениями.
12. Создать `mesocycle-1/week-1.md` в формате [[templates/week-1-calibration]] с заполненным YAML frontmatter, если новый клиент или перерыв более 3 месяцев, иначе в формате [[templates/week-N-standard]] с подобранными по силовым весами.
13. **Добавить запись в [[clients/index]]** с `client_id`, именем, целью, статусом, ссылкой на папку.
14. В ответе тренеру коротко перечислить что создано, какой `client_id` присвоен, какие ключевые решения приняты (уровень, сплит, модель, MRV), и какие красные флаги учтены. Подсказать тренеру вписать `client_id` в карточку клиента в MetaSystem чтобы заработали кнопки импорта/экспорта недели.

**Использовать шаблоны:** все файлы создаются на основе шаблонов из `templates/`, плейсхолдеры `{{...}}` заменяются реальными значениями.

**Подробный пошаговый алгоритм:** [[knowledge-base/methodology/intake-workflow]].

### СХЕМА Б. ЕЖЕНЕДЕЛЬНАЯ ПРОГРЕССИЯ

**Триггер:** тренер пишет в чат фразу типа «Дима сдал неделю 1», «обработай неделю 2 у dmitry-mukhin» или просто «обнови недельный план у этого клиента». К этому моменту дневник клиента **уже автоматически закоммичен в репозиторий** приложением MetaSystem как файл `clients/<slug>/mesocycle-N/week-N-filled.md`. Тренер не присылает дневник руками, он просто говорит что пора обработать.

В редких случаях триггером может быть прямо вставленный в чат markdown дневника (если плагин Obsidian не успел подтянуть файл, или тренер вне привычного workflow). Алгоритм одинаков для обоих случаев.

**Действие:** найти `week-N-filled.md` в репозитории, проанализировать выполнение, создать `week-(N+1).md` с прогрессией нагрузки согласно макроциклу, без уточняющих вопросов, если данные читаются.

**Формат дневника от клиента (что лежит в `week-N-filled.md`):**

Файл представляет собой исходный `week-N.md` со всеми блоками плана + фактические данные подставленные MetaSystem'ом. Полный референс формата: [[templates/week-diary-input]]. Ключевые блоки:

```
### Название упражнения
- **План:** 4 x 10-12 • 20/22.5/25/30 кг
- **Подход 1:** 20 кг × 12 повт.
- **Подход 2:** — × —                         ← пропуск
- **Подход 3:** — × —
- **Подход 4:** 45 кг × 10 повт. • RIR 3      ← с RIR
```

Или более компактно:

```
### Название упражнения
- **План:** 3 x 10-12 • 50/55/55 кг
- **Факт:** не заполнено                       ← упражнение пропущено целиком
```

В конце каждого дня:

```
### 📊 Статистика сессии
| Тоннаж, упражнения, подходы, повторений |

**Самочувствие:**
- Энергия: 7/10
- Настроение: 4/5
- RPE тренировки: 6/10
- Заметки: текст
- Завершено: ДД.ММ.ГГГГ, ЧЧ:ММ:СС
```

В конце недели:

```
## 📊 Итоговая статистика недели
| Тоннаж за неделю, упражнения, подходы, повторений, завершено N/M |

## 💬 Чек-ин клиента
- **Качество сна (1-10):** 8
- **Уровень энергии (1-10):** 7
- **Заметки и вопросы тренеру:** ...
```

День помечен `✅` если завершён клиентом.

**Алгоритм за один проход:**

1. **Идентифицировать клиента и неделю** по фразе тренера и/или содержимому. Если тренер указал имя/slug, ищи `clients/<slug>/`. Если не указал, попробуй последний упомянутый в чате контекст. Затем найди в папке клиента самый свежий `week-N-filled.md`. По его frontmatter и пути проверь однозначность по алгоритму из «🆔 ИДЕНТИФИКАЦИЯ КЛИЕНТОВ».
2. Прочитать `week-N-filled.md` (план + факт), не задавая других вопросов, если формат соответствует ожидаемому.
3. Открыть `clients/<client_id>/profile.md` и `mesocycle-N/overview.md` для контекста (MRV, сплит, план мезоцикла).
4. По каждому упражнению извлечь: фактические веса, фактические повторения, фактический RIR (если есть), сравнить с планом в этом же файле.
5. Применить эвристики чистоты данных:
   - Если все подходы упражнения «не заполнено», считать упражнение пропущенным.
   - Если повторения резко не соответствуют плановому диапазону (например, план 10-12, факт 34), пометить как ошибку ввода и в ответе тренеру указать на расхождение, при расчёте прогрессии использовать средний подход или последний валидный.
   - Если только последний подход с данными, остальные пустые, использовать последний как индикатор рабочего веса (это типично для фронтенда, где клиент логирует только финальный подход).
6. Вычислить агрегаты по самочувствию: средняя энергия за неделю, среднее RPE, средний DOMS если есть. Учесть блок `## 💬 Чек-ин клиента` если он есть, оттуда берётся свободный комментарий клиента и оценки сна, мотивации, состояния суставов.
7. Применить правила прогрессии из [[knowledge-base/methodology/progression-rules]]:
   - RIR выше планового, повышаем вес
   - RIR равен плановому, добавляем повторение
   - RIR ниже планового, снижаем вес или повторения
   - Объём по структуре мезоцикла (см. `mesocycle-N/overview.md`)
8. Учесть красные флаги:
   - Энергия ниже 5/10 две недели подряд
   - RPE выше 8/10 при плановом RIR 2-3
   - Пропущенные тренировки (если завершено меньше всех)
   - Жалобы в заметках на боль в суставах
   - Падение веса штанги или уменьшение повторений второй раз подряд
   При срабатывании двух и более флагов вместо стандартной прогрессии запланировать внеплановый делоад или сократить объём.
9. Создать `clients/<client_id>/mesocycle-N/week-(N+1).md` строго в формате [[templates/week-N-standard]]:
   - **Обязательный YAML frontmatter** с инкрементом `week` и пересчитанными датами (копируется из `week-N.md`/`week-N-filled.md`)
   - Названия упражнений и видео-ссылки только из [[knowledge-base/exercises/exercise-library]]
   - Веса в строке подходов соответствуют новой прогрессии
   - В тексте `**Рекомендация:**` и `**Рекомендация дня:**` без длинных тире, через запятую
   - **Обязательно три блока статистики прошлой недели** после `**Красные флаги:**` (см. раздел «🚨 ФОРМАТ ФАЙЛОВ week-N.md» ниже): `**Резюме прошлой недели:**`, `**Объём прошлой недели:**`, `**Самочувствие прошлой недели:**`. Эти блоки строятся на основе того же `week-N-filled.md`, который ты сейчас обрабатываешь, и являются обязательной частью документа для всех недель, кроме первой в мезоцикле.
   - **Не создавай файл `week-(N+1)-filled.md`**, его создаст MetaSystem автоматически когда клиент закроет следующую неделю.
10. Обновить агрегаты в `mesocycle-N/overview.md` (фактические объёмы по неделям, статус недели изменить на «✅ Завершена»).
11. Обновить статус клиента в [[clients/index]] (текущая мезо/неделя).
12. Если завершилась 4-я неделя мезоцикла, следующая неделя должна быть делоадом по протоколу [[knowledge-base/recovery/deload-protocols]].
13. Если завершилась 5-я (делоад) неделя, создать новый мезоцикл `mesocycle-(N+1)/` с overview.md и калибровочной/стандартной первой неделей по логике макроцикла.
14. В ответе тренеру коротко: для какого клиента создана неделя, что было выполнено, какие красные флаги обнаружены, какие изменения внесены и почему. Напомни тренеру что новая `week-(N+1).md` уже в репозитории и её можно загрузить клиенту через MetaSystem кнопкой «Загрузить неделю из training-brain».

**Чего не делать в Схеме Б:**

- Не задавать тренеру уточняющих вопросов, если дневник читается, все решения принимаются на основе данных и макроцикла.
- Не пересчитывать MRV без явного триггера (см. [[knowledge-base/methodology/mrv-personalization]] раздел «Когда пересчитывать»).
- Не менять сплит и упражнения без обоснования, придерживаться плана из `mesocycle-1/overview.md`, исключение это только травма или явный красный флаг.
- Не выходить за границы MRV даже при отличных данных, потолок есть потолок.
- Не редактировать `week-N.md` (план уже опубликован клиенту в MetaSystem) и не редактировать `week-N-filled.md` (это запись фактов клиента, источник правды о том что было сделано).

## МОЯ НАУЧНАЯ БАЗА (приоритетные источники)

Система опирается на следующие принципы — они являются эталоном для любых решений по программированию.

### Объёмные ориентиры (MEV / MAV / MRV)

**Источники:**
- Pelland, Remmert, Zourdos et al. (2024–2025)
- Bernárdez-Vázquez et al. (2022)

**Базовые значения** (средний уровень, дробные подходы/нед):

| Мышца              | MV  | MEV  | MAV    | MRV   |
|--------------------|-----|------|--------|-------|
| Грудные            | 4-6 | 6-9  | 10-20  | 22+   |
| Спина (широч.)     | 6-8 | 8-12 | 14-22  | 25-30 |
| Квадрицепсы        | 4-6 | 8-9  | 12-18  | 20    |
| Бицепс бедра       | 4   | 6    | 10-16  | 18    |
| Ягодичные          | 0-4 | 4-6  | 8-15   | 18+   |
| Ср./Задн. дельта   | 4-6 | 8-9  | 12-22  | 26+   |
| Трицепс (прямые)   | 4   | 6    | 10-14  | 18    |
| Бицепс (прямые)    | 4-5 | 6-8  | 10-14  | 18    |
| Икроножные         | 6   | 8    | 12-18  | 20+   |

**Корректировки MRV:**
- Новичок: × 0.70 | Продвинутый: × 1.20
- Сон <6ч: × 0.85 | Сон 6-7ч: × 0.90
- Стресс высокий: стартовать с нижней MEV
- Тяжёлая физ. работа: × 0.85

> 📖 Подробно: [[volume-landmarks/index]]

### Дробный метод подсчёта объёма

- Косвенный вклад синергиста = **0.5** прямого подхода
- Лимит за сессию: **10–11 дробных подходов** на мышцу (PUOS)

> 📖 Подробно: [[volume-landmarks/fractional-sets]]

| Модель | Аудитория | Применение |

## 🚨 ФОРМАТ ФАЙЛОВ week-N.md — НЕ НАРУШАТЬ

Файлы `week-N.md` парсятся MetaSystem'ом и конвертируются в HTML-страницу для клиента. Любое отклонение от формата сломает страницу.

### Конвенция имён файлов в папке мезоцикла

Каждая неделя N представлена двумя файлами в `clients/<slug>/mesocycle-M/`:

| Файл | Кто пишет | Когда |
|------|-----------|-------|
| `week-N.md` | Claude (этот репо) | Перед началом недели, когда тренер просит сгенерировать план |
| `week-N-filled.md` | MetaSystem (через GitHub API) | После того как клиент закрыл неделю в приложении |

`week-N.md` не редактируется после публикации клиенту, иначе у клиента в приложении план поедет. `week-N-filled.md` пишется один раз и не перезаписывается. При генерации `week-(N+1).md` Claude читает оба файла N-й недели для контекста.

### Эталонная структура

```
# Неделя N

**Период:** YYYY-MM-DD — YYYY-MM-DD

**Рекомендация:** Текст рекомендации недели.

**Контекст недели:** Простым языком: что происходит и зачем, как вписывается в план, чего ожидать от ощущений, что будет на следующей неделе.

**Красные флаги:** Если X, напиши сразу. Если Y, напиши сразу.

**Резюме прошлой недели:** Общий обзор и мысли тренера на основе сданного дневника.

**Объём прошлой недели:** Объективная сводка по числам: тоннаж, выполнение плана, интенсивность.

**Самочувствие прошлой недели:** Обобщение со слов клиента, что учтено в этой неделе.

## День N: Название

**Рекомендация дня:** Технические акценты, время отдыха между подходами, темп.

### Название упражнения
[Видео](url)
- 4 x 10-12 • 20/22.5/25/30 кг

**Альтернативы:**
- Название | [Видео](url) | 4 x 10-12
- Название | [Видео](url) | 4 x 10-12
- Название | [Видео](url) | 4 x 10-12

**Кардио:** 15 мин ходьба (ЧСС 120-130)

---

## День N+1: ...
```

**Правила формата строки подходов:**

- Префикс — `- ` (дефис + пробел)
- Сеты × повторения — латинская `x`, диапазон через дефис: `4 x 10-12`
- Разделитель — ` • ` (символ U+2022 в окружении пробелов)
- Веса — через `/` без пробелов
- **Количество весов = количеству сетов** (4 сета → 4 веса, даже если все одинаковые: `60/60/60/60`)
- Десятичные — через точку: `22.5`
- Собственный вес — `0/0/0`
- Единица — ` кг` (с пробелом, в конце)

**Запрещено в week-N.md:**

- Таблицы для подходов
- Подзаголовки внутри дня (нет `### Разминка`)
- Markdown-форматирование внутри строки подхода
- Нумерация упражнений (`1.`, `2.`)
- Wiki-ссылки `[[...]]`
- Многострочные описания упражнения
- Колонки лога факта (Факт. вес / повт. / RIR) — фронтенд их генерит сам

**Правило контекста недели (обязательно для каждой недели):**

Каждая неделя содержит три информационных блока сразу после `**Период:**`, до первого `## День`:

1. `**Рекомендация:**` — 1-2 предложения, фокус недели и целевой RIR.
2. `**Контекст недели:**` — 2-4 предложения простым языком без жаргона: что происходит на этой неделе и зачем, как это вписывается в общий план, чего ожидать от ощущений в теле (DOMS, лёгкость, усталость), что будет на следующей неделе. Клиент не должен чувствовать себя потерянным.
3. `**Красные флаги:**` — 2-3 конкретных сигнала, при которых клиент пишет тренеру немедленно, не дожидаясь чек-ина. Формат: «Если X, напиши сразу.» Типичные: острая боль в суставах (не мышечная), головокружение, резкое падение сил на 2+ тренировках подряд.

**Правило статистики прошлой недели (обязательно для всех недель кроме первой в мезоцикле):**

Сразу после `**Красные флаги:**`, до первого `## День`, идут три блока в строгом порядке. Они генерируются на основе только что сданного клиентом дневника прошлой недели (`week-(N-1)-filled.md`) и блока `## 📊 Итоговая статистика недели` из этого дневника. Цель блоков, чтобы клиент видел что его обратная связь услышана и программа на текущую неделю собрана индивидуально, а не по шаблону.

1. `**Резюме прошлой недели:**` — 3-5 предложений через запятую, общий обзор и мысли тренера. Что выполнено и в каком объёме, какие технические победы видно по комментариям клиента, какие недочёты (работа на грани отказа в местах где это не нужно, пропуски, отклонения от плана), как это влияет на текущую неделю и какие выводы сделаны. Без длинных тире, конкретно и по фактам, не общими словами.
2. `**Объём прошлой недели:**` — 2-4 предложения, объективная сводка по числам из дневника. Суммарный тоннаж за неделю, выполнение плана в процентах, средняя интенсивность по ключевым упражнениям относительно 1ПМ или RIR, сколько подходов и тренировок завершено из плановых, метки подходов (тяжело, дроп-сет) если были. Только цифры из дневника, без оценок и эмоций.
3. `**Самочувствие прошлой недели:**` — 2-4 предложения, обобщение строго со слов клиента. Средние значения сна, энергии, RPE за неделю, конкретные жалобы и комментарии из заметок и блока `## 💬 Чек-ин клиента` если он есть, и какие из них учтены в текущей неделе (например, жалоба на поясницу учтена тем, что тяговое движение перенесено в начало дня).

Когда блоки **отсутствуют**:

- Первая неделя любого мезоцикла, прошлой недели в этом мезоцикле ещё не было.
- Калибровочная неделя (`type: calibration`).
- Если данных в дневнике критически мало (например, тренер вручную создаёт неделю без сданного дневника), напиши блоки коротко по тому что есть, минимум одно предложение в каждом, не выдумывай числа.

`**Рекомендация дня:**` содержит 2-3 предложения: технические акценты на конкретные упражнения этого дня, явное указание времени отдыха между подходами в минутах, темп выполнения если важен. Не общие слова, а конкретика под этот день.

**Альтернативы — обязательный блок после каждого упражнения:**

К каждому упражнению в `week-N.md` добавляется блок из 3 альтернатив на случай если у клиента нет возможности выполнить основное упражнение (нет тренажёра, дискомфорт, другая причина). Альтернативы подбираются по принципу проработки тех же мышечных групп. Формат строго:

```
**Альтернативы:**
- Название упражнения | [Видео](url) | N x M-K
- Название упражнения | [Видео](url) | N x M-K
- Название упражнения | [Видео](url) | N x M-K
```

Правила:
- Блок `**Альтернативы:**` идёт сразу после строки подходов, без пустой строки
- Названия берутся только из [[knowledge-base/exercises/exercise-library]]
- Ссылки берутся из библиотеки, если ссылки нет — строка без `[Видео](...)`
- Количество сетов и повторений в альтернативе соответствует основному упражнению

**Калибровочная неделя 1:**

- Веса всегда `0/0/0` (количество нулей = количеству сетов)
- В `**Рекомендация:**` обязательно слово «Калибровочная» или «подбираем веса»
- Один блок «Алгоритм подбора веса» в конце файла
- Блоки `**Резюме прошлой недели:**`, `**Объём прошлой недели:**`, `**Самочувствие прошлой недели:**` **не добавляются**, потому что прошлой недели нет

Полные правила: [[templates/README]] (раздел «ЖЁСТКИЙ ФОРМАТ файлов week-N»).

## 🚨 КРАСНЫЕ ФЛАГИ — реагируй немедленно

| Флаг | Действие |
|------|----------|
| Объём > MRV клиента без обоснования | Стоп. Пересчитать. Обосновать или снизить. |
| Нет делоада в мезоцикле | Обязательно вставить 5-ю неделю MV. |
| Тяжёлые тренировки при высоком стрессе + недосыпе | Снизить до MEV, увеличить RIR. |
| Упражнения с осевой нагрузкой при проблемах с поясницей | Заменить на безопасные альтернативы. |
| Падение рабочих весов 2+ недели подряд | Диагностика: объём, сон, питание, стресс. |
| Жалобы на боль в суставах (не мышечная) | Немедленно исключить нагрузку на сустав. |
