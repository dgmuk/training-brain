## 🔴 ВЫСШИЙ ПРИОРИТЕТ — ЧЕТЫРЕ ПРАВИЛА, ВАЖНЕЕ ВСЕХ ОСТАЛЬНЫХ

### 🔴 ПРАВИЛО №1. Стиль речи без длинных тире

В любых ответах в чат, в любых текстах рекомендаций (в `week-N.md`, `mesocycle-overview.md`, `macrocycle/overview.md`, в комментариях клиенту, в чек-инах и в общении с тренером) запрещено использовать длинное тире (символ `—`, U+2014) как разделитель частей предложения.

Запрещён стиль вида:
- «Сегодня подбор весов. Каждое упражнение начинай с лёгкого подходящего, корректируй по факту. Ориентир — RIR 3-4 в последнем подходе. Если техника плывёт — снижай вес сразу.»

Вместо длинного тире используй запятые, союзы (потому что, чтобы, если, и, но), двоеточие, или раздели мысль на два предложения. Предпочтение отдаётся длинным предложениям через запятую, в стиле живой русской речи.

Правильно:
- «Сегодня подбор весов, каждое упражнение начинай с лёгкого подходящего и корректируй по факту, ориентир по RIR 3-4 в последнем подходе, если техника плывёт сразу снижай вес.»

Где разрешено длинное тире:
- В диапазонах чисел и дат: `2026-05-14 — 2026-05-21`, `MEV+2 → MEV+2`, формат периода в шапке `week-N.md`.
- В таблицах как разделитель ячеек или прочерк.
- В заголовках разделов внутри `knowledge-base/` если это исторически устоявшийся научный текст (но новые тексты пиши без тире).

Это правило приоритетнее всех остальных стилевых норм. Если возникает конфликт между лаконичностью и этим правилом, выигрывает это правило.

### 🔴 ПРАВИЛО №2. Имена упражнений и видео-ссылки только из библиотеки

Единственный источник правды для названий упражнений и ссылок на YouTube видео это файл [[knowledge-base/exercises/exercise-library]].

Правила:
1. При составлении любой `week-N.md` бери имя упражнения из библиотеки буква-в-букву, регистр и пунктуация должны совпадать.
2. Ссылку `[Видео](url)` подставляй только ту, которая указана в библиотеке для этого упражнения, не выдумывай ссылки.
3. Если в библиотеке для упражнения стоит плейсхолдер `https://...` или ссылки нет, не вставляй строку `[Видео](...)` в `week-N.md`, оставь только заголовок упражнения и строку подходов, и сообщи тренеру о пропуске в библиотеке отдельным предложением в ответе.
4. Если нужного упражнения в библиотеке нет вообще, не добавляй его в программу самостоятельно, выбери ближайшую альтернативу из библиотеки и предупреди тренера, либо попроси добавить упражнение в библиотеку перед публикацией недели.
5. При добавлении нового упражнения в библиотеку соблюдай формат блока, описанный в самой библиотеке.

Это правило обязательно для любых файлов программ (`week-N.md`, шаблоны мезоциклов, готовые программы). В обычной переписке с тренером можно упоминать упражнения свободнее.

### 🔴 ПРАВИЛО №3. Краткость верхних текстовых блоков недели

Клиент читает программу с телефона на ходу или между подходами в зале. Длинные простыни текста и большие таблицы сравнения он просто не прочитает, и вся проделанная работа окажется напрасной.

Жёсткие лимиты на блоки в начале `week-N.md` (до первого `## День`):

| Блок | Максимум | Что писать |
|------|----------|------------|
| `**Резюме прошлой недели:**` | 3 предложения | Итог в процентах попадания, человек человеку. Только для нед 2+. |
| `**Рекомендация:**` | 2 предложения | Фокус недели, целевой RIR |
| `**Контекст недели:**` | 3 предложения | Что меняется и зачем, чего ждать в теле |
| `**Красные флаги:**` | 3 пункта | «Если X, напиши сразу» |
| `**По чек-ину:**` | 3 предложения | Кратко по ответам клиента, без полного анализа |
| `**Объём недели:**` | 2 предложения | Где добавили или убрали подходы |
| `**Что меняем по сравнению с прошлой неделей:**` | до 7 пунктов | По одному на упражнение, формат: `- Упражнение, было/стало, причина в 3-4 словах` |
| `**Рекомендация дня:**` | 6 предложений | Технические акценты, отдых, темп, плюс обязательный блок разминки и заминки по ПРАВИЛУ №4 |

**Запрещено:**

- Длинные абзацы 5+ предложений в любом из этих блоков.
- Огромная таблица «Сводка изменений нед N → нед N+1» с колонками `план / факт / план / причина` по каждому упражнению. Вместо этого короткий маркированный список `**Что меняем по сравнению с прошлой неделей:**` 3-7 пунктов, плюс короткое `**Резюме прошлой недели:**` в процентах.
- Дублирование информации между `**Рекомендация:**` и `**Контекст недели:**`.
- Перечисление каждого упражнения внутри `**Контекст недели:**` или внутри `**Резюме прошлой недели:**`, для этого есть `**Что меняем**`.

**Принцип:** если тренер хочет рассказать клиенту больше деталей о прошлой неделе, это идёт коротко в `**Резюме прошлой недели:**` и `**Что меняем**`, не в простыне абзацев и не в таблицах. Полный разбор по каждому упражнению с цифрами и причинами тренер держит у себя в `mesocycle-N/overview.md`, а не в `week-N.md`. Файл `week-N.md` это документ для клиента, не отчёт для самого себя.

Это правило приоритетнее правила «дать клиенту максимум контекста». Лучше короткий блок который прочитают, чем длинный который пропустят.

#### Алгоритм заполнения `**Резюме прошлой недели:**`

Блок обязателен для нед 2+ (в нед 1 нечего резюмировать). Главное в нём, процент попадания по плану. Считается так:

1. Для каждого выполненного подхода (с фактом) определяем корзину:
   - **В плане**, если фактический вес попадает в плановый диапазон или равен плановому, и фактические повторения в плановом диапазоне.
   - **Выше плана**, если фактический вес выше планового или клиент сделал больше повторений чем верх диапазона при плановом весе. Это значит для клиента было слишком легко.
   - **Ниже плана**, если фактический вес ниже планового или повторений меньше чем низ диапазона. Это значит клиент забуксовал или вес был тяжелее чем нужно.
2. Считаем процент каждой корзины от общего числа выполненных подходов с фактом.
3. Округляем до 5%.
4. В предложении даём оценку: «хорошая динамика» если в плане 60%+, «отлично» если 75%+, «отстаёшь» если ниже 50% и больше половины ниже плана.

Стиль, человек человеку, без жаргона. Примеры правильных формулировок:

- «На прошлой неделе 80% подходов попали в плановый диапазон, 15% оказались легче чем нужно, 5% ниже плана. Это хорошая динамика для второй недели мезоцикла, продолжаем накопление.»
- «По итогам недели 50% в плане, 40% выше плана, 10% ниже. Это означает что веса первой недели были занижены, теперь подвинул цифры вверх где запас был очевиден.»
- «Ты сделал 3 из 3 тренировок, 70% подходов попали в плановый коридор, 25% выше плана и 5% ниже. Хорошо двигаешься, на этой неделе добавляю интенсивность там где было слишком легко.»

В этом блоке нельзя:

- Перечислять каждое упражнение, для этого есть `**Что меняем**`.
- Использовать длинные тире.
- Писать абзацы по 5+ предложений.

### 🔴 ПРАВИЛО №4. Обязательная разминка и заминка в каждом дне

В каждом тренировочном дне `**Рекомендация дня:**` обязательно содержит два дополнительных мини-блока в конце: разминка и заминка. Это общее правило для всех клиентов, формулировка стандартная и не выдумывается на каждую неделю заново. Цель, чтобы клиент никогда не выходил на рабочие подходы холодным и не пропускал восстановительные процедуры после тренировки.

#### Стандартная формулировка (копируется в каждый день)

```
**Разминка:** Общая 5-10 минут лёгкого кардио (велотренажёр, эллипс или быстрая ходьба) до лёгкой испарины, дальше суставная гимнастика, круговые движения в плечах, локтях, тазобедренных, коленях и голеностопах по 10 повторений в каждую сторону, разогреваем суставо-связочный аппарат. Перед каждым базовым упражнением добавь 2 разминочных подхода с весом около 40% от рабочего по 6-10 повторений, перед изоляцией достаточно одного лёгкого подхода 10-12 повторений.

**Заминка:** 5 минут лёгкого кардио на снижение пульса, дальше МФР (массажный ролл) по проработанным сегодня группам по 60 секунд на каждую, и статическая растяжка нагруженных мышц по 30 секунд на каждую сторону.
```

#### Где и как пишется

- В каждом `## День N: Название` блок `**Рекомендация дня:**` содержит сначала технические акценты дня (1-3 предложения) и время отдыха, затем `**Разминка:**` и `**Заминка:**` отдельными подблоками.
- Пример итоговой структуры рекомендации дня:

```markdown
**Рекомендация дня:** Силовой день, диапазон 5-8 повторений, отдых 2-3 минуты. В жиме на 80 кг локти под 45° к корпусу, лопатки сведены. В приседе на 65 кг опускание 2-3 секунды, колени по носкам.

**Разминка:** Общая 5-10 минут лёгкого кардио до лёгкой испарины, далее суставная гимнастика, круговые движения в плечах, локтях, тазобедренных, коленях и голеностопах по 10 повторений в каждую сторону. Перед жимом и приседом добавь 2 разминочных подхода с весом около 40% от рабочего по 6-10 повторений.

**Заминка:** 5 минут лёгкого кардио на снижение пульса, далее МФР по сегодняшним группам по 60 секунд на группу и статическая растяжка нагруженных мышц по 30 секунд на сторону.
```

#### Когда можно сокращать

- В калибровочной неделе 1 (тип `calibration`) разминка обязательна, заминку допустимо упростить до строки «5 минут лёгкого кардио и растяжка нагруженных мышц», потому что калибровочная сессия короткая.
- В делоадной неделе (тип `deload`) разминку можно сократить до 5 минут общего кардио и одного лёгкого подхода перед каждым упражнением, заминка остаётся в полном виде.
- Если у клиента в профиле явно указано ограничение, например проблемы с плечом, замени круговые движения в плечах на безопасные альтернативы (вращения с минимальной амплитудой) и упомяни это в `**Разминка:**` адресно.

#### Что нельзя

- Опускать блок `**Разминка:**` или `**Заминка:**` ни в одном тренировочном дне любой `week-N.md`.
- Писать «разминка обязательна» без конкретики, формулировка должна давать клиенту шаги к действию.
- Использовать длинные тире в этих блоках, действуют все правила ПРАВИЛА №1.
- Дублировать разминку и заминку в самом начале недели в `**Контекст недели:**` или в `**Рекомендация:**`, эти блоки не для технических деталей дня, разминка живёт только внутри `**Рекомендация дня:**`.

Это правило действует независимо от длины основной части `**Рекомендация дня:**`. Лимит на основную часть остаётся 3 предложения, плюс отдельные подблоки `**Разминка:**` и `**Заминка:**` со стандартной формулировкой выше.

## 🆔 ИДЕНТИФИКАЦИЯ КЛИЕНТОВ — для масштаба 40+

> Когда клиентов становится много, без чёткой идентификации система сломается. Этот раздел задаёт три уровня идентификации, которыми пользуется любая модель в любой сессии.

### Три уровня идентификации

**Уровень 1. YAML frontmatter в файле week-N.md (главный)**

Каждый план и дневник содержит блок в самом начале файла:

```yaml
---
client_id: dimon
client_name: Дмитрий
mesocycle: 1
week: 1
period_start: 2026-05-11
period_end: 2026-05-17
type: standard
---
```

Если frontmatter есть, идентификация однозначная, ничего больше искать не нужно.

**Уровень 2. Имя файла и путь**

`clients/dimon/mesocycle-1/week-1.md` уже содержит client_id и mesocycle/week. Если frontmatter повреждён, используется путь.

**Уровень 3. Текст и контекст чата**

Только если первые два уровня не дают ответа. Используются: подпись «Клиент: ...» в дневнике, последний клиент в текущем чате, диапазон дат `period_start/period_end` для сужения поиска.

### Реестр клиентов

Все клиенты с их `client_id`, текущим статусом и активными мезо/неделями зарегистрированы в [[clients/index]]. Это единственный источник правды для определения «есть ли такой клиент».

При создании нового клиента (Схема А) обязательное действие, добавить строку в этот реестр. Без записи в реестре клиент в системе не существует.

### Алгоритм идентификации при еженедельной прогрессии

```
ШАГ 1. Прочитать YAML frontmatter входящего дневника
   → если есть client_id, mesocycle, week
   → перейти к ШАГ 5 (создание следующей недели)

ШАГ 2. Если frontmatter нет, извлечь из содержимого
   → заголовок «# Неделя N» даёт N
   → блок «**Период:** YYYY-MM-DD — YYYY-MM-DD» даёт диапазон дат
   → подпись/упоминание клиента в тексте
   → перейти к ШАГ 3

ШАГ 3. Сопоставить с реестром clients/index.md
   → найти клиента по имени или периоду активного мезо
   → если совпадение однозначное, перейти к ШАГ 5
   → если несколько кандидатов или ноль, перейти к ШАГ 4

ШАГ 4. Спросить тренера
   → перечислить кандидатов из реестра с их client_id
   → попросить уточнить
   → НЕ создавать week-(N+1).md до уточнения

ШАГ 5. Открыть mesocycle-N/overview.md клиента
   → проверить что week из дневника совпадает с активной неделей
   → если расхождение, спросить тренера до создания

ШАГ 6. Создать week-(N+1).md в нужной папке клиента
   → обязательно с YAML frontmatter
   → client_id, client_name, mesocycle, week+1, новые даты, type
```

### Правила создания client_id (slug)

При первом касании с клиентом (Схема А) формирую client_id по правилам:

1. Только латиница в нижнем регистре, цифры и дефис.
2. Транслитерация по читаемости: Дмитрий → `dmitry`, Александр Попов → `aleksandr-popov`, Ольга Иванова → `olga-ivanova`.
3. Если slug уже занят в реестре, добавить фамилию или цифровой суффикс (`aleksandr-popov-2`).
4. Slug фиксируется на старте и не меняется никогда.

### Что должно быть во frontmatter

Поля и их назначение:

| Поле | Обязательно | Назначение |
|------|-------------|------------|
| `client_id` | да | Slug, по нему находится папка |
| `client_name` | да | Читаемое имя для контекста |
| `mesocycle` | да | Номер мезоцикла |
| `week` | да | Номер недели в мезоцикле |
| `period_start` | да | Дата начала недели, ISO YYYY-MM-DD |
| `period_end` | да | Дата конца недели, ISO YYYY-MM-DD |
| `type` | да | `standard` / `calibration` / `deload` |

Этот frontmatter **обязателен в каждом week-N.md**, в шаблонах он уже есть как заготовка.

### Применимость по сценариям

- При создании нового клиента (Схема А), frontmatter заполняется на основе анкеты.
- При еженедельной прогрессии (Схема Б), frontmatter копируется из предыдущей недели с инкрементом `week` и пересчётом дат.
- Приложение клиента, которое генерирует дневник, **не модифицирует** frontmatter, передаёт его в неизменном виде.

## 🔁 ПРОТОКОЛ ВЗАИМОДЕЙСТВИЯ — План А (онлайн) и План В (офлайн)

> Это операционный контракт между тренером и моделью. Любая модель в любой сессии должна работать по этим схемам автоматически, без уточняющих вопросов, если входные данные соответствуют формату.
>
> **План А (онлайн):** клиент с приложением. Схема А это первое касание (создание клиента), Схема Б это еженедельная прогрессия по дневнику из приложения. Веса прописаны в week-N.md.
>
> **План В (офлайн), по умолчанию для офлайн-клиентов:** клиент тренируется в зале с тренером, приложения нет. Мезоцикл расписывается целиком, веса по факту, недели в `program/`, факт-таблицы в `fakt/`, прогрессия следующего мезо по отчёту тренера.

### СХЕМА А. ПЕРВОЕ КАСАНИЕ С КЛИЕНТОМ

**Триггер:** тренер прислал заполненную анкету нового клиента (формат [[templates/client-questionnaire]]) или текст в свободной форме с этими полями.

**Действие:** сразу создать полную папку клиента целиком, без уточняющих вопросов, чтобы у тренера была вся картина.

**Что создаём за один проход:**

```
clients/<имя-латиницей>/
├── README.md                        ← навигация
├── questionnaire-raw.md             ← оригинальная анкета без редактуры
├── profile.md                       ← обработанный профиль с расчётами MEV/MAV/MRV
├── macrocycle/
│   ├── overview.md                  ← 6-месячный план (5-6 мезо)
│   └── strategy.md                  ← обоснование выбора моделей и сплита
└── mesocycle-1/
    ├── overview.md                  ← план мезоцикла для тренера
    └── week-1.md                    ← калибровочная неделя в формате парсера
```

**Алгоритм за один проход:**

1. Прочитать анкету, валидировать данные на правдоподобность и противоречия.
2. **Сформировать `client_id`** по правилам из раздела «🆔 ИДЕНТИФИКАЦИЯ КЛИЕНТОВ» (slug на латинице).
3. **Проверить уникальность `client_id`** в [[clients/index]], если занят, добавить суффикс.
4. Проверить медицинский допуск по [[knowledge-base/contraindications/medical-clearance]], если красный свет, остановиться и сообщить тренеру до создания файлов.
5. Создать папку `clients/<client_id>/` и все 6 файлов выше.
6. Объективно оценить уровень клиента по силовым в анкете, не доверять самооценке.
7. Рассчитать персональные MEV/MAV/MRV по [[knowledge-base/methodology/mrv-personalization]] и внести в profile.md.
8. Выбрать сплит по [[knowledge-base/methodology/split-selection]] и обосновать в strategy.md.
9. Выбрать модель периодизации по [[knowledge-base/periodization/models]].
10. **Выбрать шаблон макроцикла по цели клиента:**
    - Цель «набор массы» / «гипертрофия» / «общая форма» → [[knowledge-base/macrocycle/mass-gain-template]]
    - Цель «максимальная сила» / «жим лёжа» / «пауэрлифтинг» / «выйти на разряд» → [[knowledge-base/macrocycle/strength-template]]
    - Если в анкете явно указано «специализация на жиме» или клиент жимовик-федерат → дополнительно применить [[knowledge-base/methodology/bench-specialization]]
    - Цель «похудение» / «снижение веса» → стандартный шаблон с поправкой по [[knowledge-base/fat-loss/programming]]
11. **Применить специфику клиента поверх выбранного шаблона:**
    - Клиент-женщина любого возраста до 40 → [[knowledge-base/female-physiology/hypertrophy-women]] для расчёта MEV/MAV/MRV с поправкой на пол
    - Клиентка на гормональной контрацепции → дополнительно [[knowledge-base/female-physiology/contraception-effect]]
    - Клиентка отслеживает цикл и хочет учитывать фазы → [[knowledge-base/female-physiology/cycle-aware-programming]]
    - Клиентка 40+ с симптомами перименопаузы или старше 45 → [[knowledge-base/female-physiology/perimenopause]]
    - Клиент любого пола 40+ → [[knowledge-base/methodology/aging-trainees]] для возрастных корректировок MRV, частоты, отдыха
    - Клиент-мужчина 40-50 + женщина в перименопаузе одновременно → применять обе методички, женская приоритетна по фазам, возрастная по объёму
    - Клиент с проблемами поясницы → дополнительно [[knowledge-base/contraindications/lower-back]]
    - Клиент с проблемами плеча → дополнительно [[knowledge-base/contraindications/shoulders]]
    - Клиент с проблемами колена → дополнительно [[knowledge-base/contraindications/knees]]
    - Клиент с ССЗ или гипертонией → дополнительно [[knowledge-base/contraindications/cardiovascular]] (с обязательным медицинским допуском)
    - Клиент с дефицитом времени (2-3 тренировки в неделю по 30-45 мин) → [[knowledge-base/methodology/minimalist-programming]]
    - Клиент с параллельной тренировкой силы и выносливости (бег, велосипед, гибридные старты) → [[knowledge-base/methodology/concurrent-training]]
    - Кардио в любой программе → [[knowledge-base/methodology/cardio-prescription]] для дозировки по цели
12. **Отобрать упражнения для каждого тренировочного дня по [[knowledge-base/methodology/exercise-selection]]:**
    - Главные компаунды на день, второй компаунд под другим углом, изоляция с длинными позициями
    - Проверить SFR каждого упражнения, при низком SFR искать альтернативу с тем же паттерном
    - Назначить целевой RIR по [[knowledge-base/methodology/proximity-to-failure]]: главные компаунды RIR 1-3, изоляция RIR 0-2
    - Имена упражнений только из [[knowledge-base/exercises/exercise-library]]
    - Считать дробный объём ([[knowledge-base/volume-landmarks/fractional-sets]]), не превышать PUOS 10-11 на мышцу за сессию
    - Если у клиента есть явно отстающая группа и стаж 1.5+ лет → запланировать [[knowledge-base/methodology/specialization-phase]] для одного из мезоциклов в макро (не первого)
13. Распланировать макроцикл в `macrocycle/overview.md` по выбранному шаблону:
    - Под массу, 6 месяцев (5-6 мезо с прогрессией MEV+2 между ними)
    - Под силу, 16-24 недели (3-4 блока + пик + тест 1RM по [[knowledge-base/methodology/1rm-testing-protocol]])
14. Создать `mesocycle-1/overview.md` с планом 5 недель, объёмом и упражнениями.
    - Если выбран силовой шаблон, мезоциклы строятся по [[knowledge-base/periodization/strength-block]] (блоки гипертрофия → сила → реализация), в `overview.md` указывается какой это блок и какова доля % 1RM.
    - В гипертрофическом мезоцикле RIR прогрессирует по фазам ([[knowledge-base/methodology/proximity-to-failure]]), интенсификационные техники ([[knowledge-base/methodology/intensification-techniques]]) применяются только в нед 3-4
15. Создать `mesocycle-1/week-1.md` в формате [[templates/week-1-calibration]] с заполненным YAML frontmatter, если новый клиент или перерыв более 3 месяцев, иначе в формате [[templates/week-N-standard]] с подобранными по силовым весами.
16. **Добавить запись в [[clients/index]]** с `client_id`, именем, целью, статусом, ссылкой на папку.
17. В ответе тренеру коротко перечислить что создано, какой `client_id` присвоен, какие ключевые решения приняты (уровень, сплит, модель периодизации, выбранный шаблон макроцикла, MRV с применёнными возрастными и половыми поправками), и какие красные флаги учтены.

**Использовать шаблоны:** все файлы создаются на основе шаблонов из `templates/`, плейсхолдеры `{{...}}` заменяются реальными значениями.

**Подробный пошаговый алгоритм:** [[knowledge-base/methodology/intake-workflow]].

### СХЕМА Б. ЕЖЕНЕДЕЛЬНАЯ ПРОГРЕССИЯ

**Триггер:** тренер прислал заполненный клиентом дневник недели (markdown-файл или текст в формате, описанном ниже).

**Действие:** проанализировать выполнение, создать `week-(N+1).md` с прогрессией нагрузки согласно макроциклу, без уточняющих вопросов, если данные читаются из дневника.

**Формат дневника от клиента (что приходит на вход):**

Дневник представляет собой исходный `week-N.md`, в который приложение клиента подставило фактические данные. Ключевые блоки данных:

```
### Название упражнения
- **План:** 4 x 10-12 • 20/22.5/25/30 кг
- **Подход 1:** 20 кг × 12 повт.
- **Подход 2:** — × —                         ← пропуск
- **Подход 3:** — × —
- **Подход 4:** 45 кг × 10 повт. • RIR 3      ← с RIR
```

Или более компактно:

```
### Название упражнения
- **План:** 3 x 10-12 • 50/55/55 кг
- **Факт:** не заполнено                       ← упражнение пропущено целиком
```

В конце каждого дня:

```
### 📊 Статистика сессии
| Тоннаж, упражнения, подходы, повторений |

**Самочувствие:**
- Энергия: 7/10
- Настроение: 4/5
- RPE тренировки: 6/10
- Заметки: текст
- Завершено: ДД.ММ.ГГГГ, ЧЧ:ММ:SS
```

В конце недели:

```
## 📊 Итоговая статистика недели
| Тоннаж за неделю, упражнения, подходы, повторений, завершено N/M |
```

День помечен `✅` если завершён клиентом.

**Алгоритм за один проход:**

1. **Идентифицировать клиента** по алгоритму из раздела «🆔 ИДЕНТИФИКАЦИЯ КЛИЕНТОВ»: YAML frontmatter → имя файла → реестр → контекст. Если идентификация неоднозначная, остановиться и спросить тренера, не создавать файлы.
2. Прочитать дневник, не задавая других вопросов, если формат соответствует ожидаемому.
3. Открыть `clients/<client_id>/profile.md` и `mesocycle-N/overview.md` для контекста (MRV, сплит, план мезоцикла).
4. По каждому упражнению извлечь: фактические веса, фактические повторения, фактический RIR (если есть), сравнить с планом.
5. Применить эвристики чистоты данных:
   - Если все подходы упражнения «не заполнено», считать упражнение пропущенным.
   - Если повторения резко не соответствуют плановому диапазону (например, план 10-12, факт 34), пометить как ошибку ввода и в ответе тренеру указать на расхождение, при расчёте прогрессии использовать средний подход или последний валидный.
   - Если только последний подход с данными, остальные пустые, использовать последний как индикатор рабочего веса (это типично для фронтенда, где клиент логирует только финальный подход).
6. Вычислить агрегаты по самочувствию: средняя энергия за неделю, среднее RPE, средний DOMS если есть.
7. **Посчитать процент попадания по плану** (для блока `**Резюме прошлой недели:**`): для каждого выполненного подхода определить корзину «в плане / выше плана / ниже плана» по правилам из ПРАВИЛА №3, посчитать проценты, округлить до 5%. Эти цифры пойдут в первый текстовый блок новой недели.
8. Применить правила прогрессии из [[knowledge-base/methodology/progression-rules]]:
   - RIR выше планового, повышаем вес
   - RIR равен плановому, добавляем повторение
   - RIR ниже планового, снижаем вес или повторения
   - Объём по структуре мезоцикла (см. `mesocycle-N/overview.md`)
9. Учесть красные флаги:
   - Энергия ниже 5/10 две недели подряд
   - RPE выше 8/10 при плановом RIR 2-3
   - Пропущенные тренировки (если завершено меньше всех)
   - Жалобы в заметках на боль в суставах
   - Падение веса штанги или уменьшение повторений второй раз подряд
   При срабатывании двух и более флагов вместо стандартной прогрессии запланировать внеплановый делоад или сократить объём.
10. Создать `clients/<client_id>/mesocycle-N/week-(N+1).md` строго в формате [[templates/week-N-standard]]:
    - **Обязательный YAML frontmatter** с инкрементом `week` и пересчитанными датами
    - Названия упражнений и видео-ссылки только из [[knowledge-base/exercises/exercise-library]]
    - Веса в строке подходов соответствуют новой прогрессии
    - **Первым текстовым блоком после `**Период:**` идёт `**Резюме прошлой недели:**`** с процентами попадания и оценкой динамики, по алгоритму из ПРАВИЛА №3
    - В тексте `**Рекомендация:**`, `**Контекст недели:**`, `**Красные флаги:**`, `**По чек-ину:**`, `**Объём недели:**`, `**Что меняем:**` и `**Рекомендация дня:**` соблюдай лимиты длины из ПРАВИЛА №3 и без длинных тире
    - Разбор по каждому упражнению с цифрами и причинами оформляй в `**Что меняем по сравнению с прошлой неделей:**` маркированным списком 3-7 пунктов, не таблицей
    - Полный детальный разбор «план / факт / план / причина» по каждому упражнению идёт в `mesocycle-N/overview.md` для тренера, не в `week-N.md` для клиента
11. Обновить агрегаты в `mesocycle-N/overview.md` (фактические объёмы по неделям, статус недели изменить на «✅ Завершена»).
12. Обновить статус клиента в [[clients/index]] (текущая мезо/неделя).
13. Если завершилась 4-я неделя мезоцикла, следующая неделя должна быть делоадом по протоколу [[knowledge-base/recovery/deload-protocols]].
14. Если завершилась 5-я (делоад) неделя, создать новый мезоцикл `mesocycle-(N+1)/` с overview.md и калибровочной/стандартной первой неделей по логике макроцикла.
15. **Если клиент работает по силовому шаблону** ([[knowledge-base/macrocycle/strength-template]]):
    - Применять прогрессию из [[knowledge-base/periodization/strength-block]], в силовом блоке главный измеритель не объём а интенсивность в % 1RM
    - В блоке силы и реализации использовать RPE-автрорегуляцию по [[knowledge-base/methodology/rpe-autoregulation]] для корректировки веса главного движения
    - За 3 недели до запланированного теста или соревнования включать тейпер по [[knowledge-base/methodology/peaking-protocols]]
    - Неделя теста создаётся как отдельный документ с протоколом по [[knowledge-base/methodology/1rm-testing-protocol]], а не как стандартная week-N.md
    - После теста обязательная неделя восстановительного делоада, потом новый макроцикл с обновлённой базой 1RM
16. **Если клиентка-женщина или клиент 40+:**
    - Применить шаги прогрессии и шаги веса по правилам [[knowledge-base/female-physiology/hypertrophy-women]] и [[knowledge-base/methodology/aging-trainees]] (меньшие шаги веса, чаще прогрессия по повторениям)
    - В чек-ине у женщины смотреть `day_of_cycle` и `pms_symptoms` если они заполнены, при лютеиновой фазе или сильном ПМС снимать тяжёлые подходы и не реагировать на сниженный RIR как на проблему
    - У клиента 40+ при сигналах недовосстановления (DOMS дольше 48 часов, ЧСС покоя выше нормы 3 дня подряд, плохой сон) ставить внеплановый делоад на 5-7 дней не дожидаясь плановой 5-й недели
    - Не пересчитывать MRV в сторону роста на лютеиновых неделях у женщин и в недели после плохого сна у возрастных клиентов
17. **Поведенческое сопровождение** по [[knowledge-base/methodology/adherence-protocols]]:
    - Если клиент пропустил 1 тренировку, прогрессия не пересчитывается, переход к следующей по плану
    - Если пропущено 2-3 подряд, при возврате первая неделя на 80% от плановых весов
    - Если пропущена 1+ неделя, восстановительная неделя с объёмом минус 40% и весами минус 10-15%
    - Если пропущен 1+ месяц, переход на rebuild-протокол [[knowledge-base/methodology/return-after-break]]
    - Если attendance меньше 70% планового 2 недели подряд, инициировать разговор и возможно перевод на минималистичную программу [[knowledge-base/methodology/minimalist-programming]]
    - В чек-ин включены поля attendance, motivation, life_stress
18. В ответе тренеру коротко: для какого клиента создана неделя, что было выполнено, какие красные флаги обнаружены, какие изменения внесены и почему.

**Чего не делать в Схеме Б:**

- Не задавать тренеру уточняющих вопросов, если дневник читается, все решения принимаются на основе данных и макроцикла.
- Не пересчитывать MRV без явного триггера (см. [[knowledge-base/methodology/mrv-personalization]] раздел «Когда пересчитывать»).
- Не менять сплит и упражнения без обоснования, придерживаться плана из `mesocycle-1/overview.md`, исключение это только травма или явный красный флаг.
- Не выходить за границы MRV даже при отличных данных, потолок есть потолок.

### ПЛАН В. ОФЛАЙН-КЛИЕНТ (по умолчанию для офлайн-клиентов)

> **Терминология.** Есть два плана работы по способу ведения клиента:
> - **План А (онлайн).** Клиент с приложением, работает по Схеме А (первое касание) и Схеме Б (еженедельная прогрессия по дневнику). Веса прописаны в week-N.md, фронтенд парсит файлы.
> - **План В (офлайн), по умолчанию для офлайн-клиентов.** Клиент тренируется лично в зале с тренером, приложения нет. Веса выставляет тренер на месте по RIR, в файлах стоит маркер `вес по факту`. Мезоцикл расписывается целиком за один проход, прогрессия следующего мезо строится по короткому отчёту тренера, а не по дневнику из приложения.
>
> Если клиент офлайн, по умолчанию работаем по Плану В. Слова «сценарий С» или «план С» не используем, это устаревшее название, теперь только План В.

**Триггер:** тренер прислал короткую анкету по клиенту, с которым работает лично в зале (а не онлайн через приложение). В сообщении явно указан или подразумевается офлайн-формат, либо тренер просит «расписать сразу весь первый мезоцикл, веса я выставлю на месте».

**Отличия Плана В от Плана А (Схем А и Б):**

1. **Папка клиента имеет суффикс `-offline`** в `client_id`, например `nikita-zaharov-offline`. Это видно сразу и в реестре, и в путях.
2. **Файлы week-N.md не идут в парсер приложения**, потому что у клиента нет приложения. Они нужны самому тренеру как карточка для зала. Поэтому жёсткий формат строки подходов сохраняется (для единообразия с остальной системой и переноса в онлайн при желании), но вместо весов пишется маркер `вес по факту`.
3. **Калибровочной недели нет**. Тренер на месте видит клиента и сам подбирает рабочий вес по RIR. Стартует сразу с week-1 в стандартном виде без рабочих весов.
4. **Первый мезоцикл расписывается полностью за один проход**, все 5 недель сразу (нед 1-4 + делоад). Тренер не возвращается к модели после каждой недели, он работает с клиентом весь мезоцикл по созданному плану.
5. **Недели лежат в подпапке `program/`, а факт пишется в подпапку `fakt/`**. Для каждой недели создаётся парный файл `week-N-fakt.md` с пустыми таблицами под заполнение тренером (см. ниже). Это замена дневника из приложения.
6. **Чек-ин формата приложения не нужен**. Вместо него тренер заполняет факт-таблицы в `fakt/` и блок «Отчёт тренера после мезо» в `mesocycle-N/overview.md`. На основе этого строится следующий мезо.
7. **Frontmatter дополняется полем `mode: offline`** для маркировки.

**Что создаём за один проход (как в Схеме А, но без шага калибровки):**

```
clients/<client_id>-offline/
├── README.md
├── questionnaire-raw.md             ← мини-анкета или текст тренера как есть
├── profile.md                       ← профиль с расчётами MEV/MAV/MRV
├── macrocycle/
│   ├── overview.md                  ← 6-месячный план
│   └── strategy.md                  ← обоснование сплита и моделей
└── mesocycle-1/
```

**Алгоритм за один проход:**

1. Прочитать мини-анкету тренера, валидировать, при пропусках достроить разумные дефолты (сон 7-8 часов, стресс 4-5/10, работа смешанная) и явно перечислить эти допущения в ответе.
2. Сформировать `client_id` с суффиксом `-offline` (например `nikita-zaharov-offline`).
3. Проверить уникальность slug в [[clients/index]], добавить запись в реестр со статусом 🟢 Офлайн и текущей мезо/неделей.
4. Проверить медицинский допуск и противопоказания, при необходимости подключить файлы из [[knowledge-base/contraindications]] (например, [[knowledge-base/contraindications/lower-back]], [[knowledge-base/contraindications/cardiovascular]]) и [[knowledge-base/methodology/aging-trainees]] для клиентов 40+.
5. Рассчитать персональные MEV/MAV/MRV по [[knowledge-base/methodology/mrv-personalization]] с теми же коэффициентами, что и для онлайн-клиентов.
6. Выбрать сплит и модель периодизации, записать решения в `macrocycle/strategy.md`.
7. Выбрать шаблон макроцикла по цели:
   - Под массу или эстетику → [[knowledge-base/macrocycle/mass-gain-template]]
   - Под силу или специализацию на жиме → [[knowledge-base/macrocycle/strength-template]] плюс [[knowledge-base/methodology/bench-specialization]]
   - Гибрид массы и силы (типичный офлайн-запрос) → mass-gain-template как база, с силовыми блоками внутри отдельных мезо.
8. Расписать макроцикл на 6 мес, 5-6 мезо, в `macrocycle/overview.md`.
9. Расписать мезо 1 целиком в `mesocycle-1/overview.md` с прогрессией объёма по неделям, RIR и упражнениями. В блоке «Лог-файлы недель» ссылки идут на `program/week-N`, рядом пометка что факт лежит в `fakt/`.
10. Создать все 5 недель в `mesocycle-1/program/` (`week-1.md ... week-5-deload.md`) за один проход. В каждой неделе:
    - Frontmatter полный, с полем `mode: offline`.
    - В строке подходов вместо весов пишется `вес по факту`. Формат строки: `- 4 x 5-8 • вес по факту` (без ` кг`).
    - В блоке `**Рекомендация:**` прямо указывается: «Веса проставляются тренером на месте, ориентир по RIR X-Y в последнем подходе».
    - Все остальные правила (имена упражнений из библиотеки, обязательная разминка/заминка, блок альтернатив, ПРАВИЛО №3 на длину, ПРАВИЛО №1 на стиль речи без длинных тире) действуют без изменений.
    - Блок `**Резюме прошлой недели:**` в офлайн не пишется (нет дневника), вместо него в нед 2-4 короткий `**Контекст недели:**` про прогрессию и `**Что меняем:**` относительно предыдущей.
    - Блока `**Чек-ин в конце недели:**` для клиента не пишется (его задаёт тренер устно).
11. Создать в `mesocycle-1/fakt/` парный файл на каждую неделю (`week-1-fakt.md ... week-5-deload-fakt.md`) по правилам формата факт-таблиц ниже.
12. В конце ответа кратко отчитаться тренеру: создан клиент, какие ключевые решения приняты, какие пробелы в библиотеке упражнений всплыли (если использовались упражнения без видео или нашлись пустые разделы), что приходится присылать после мезо.

**Формат файлов факт-таблиц (`fakt/week-N-fakt.md`):**

Это пустые таблицы под заполнение тренером, замена дневника из приложения. Правила:

- Файл содержит только заголовок недели и по одной таблице на каждый тренировочный день, ничего лишнего (без рекомендаций, разминки, альтернатив, чек-ина).
- Заголовок дня совпадает с днём из соответствующего `program/week-N.md` (например `## День 1: Upper A (Пн)`).
- Колонки строго в таком порядке: `Упражнение | Повт. ном. | Повт. факт. | Факт. вес | RIR | Комментарий тренера`.
- `Повт. ном.` (номинал) предзаполняется диапазоном повторений из программы этой недели для этого упражнения (например `5-8`). Для планки и статики пишется время (`30-60 сек`).
- Остальные колонки (`Повт. факт.`, `Факт. вес`, `RIR`, `Комментарий тренера`) оставляются пустыми, тренер заполняет на тренировке.
- Список упражнений и номинальные диапазоны берутся ровно из главных строк подходов соответствующей недели программы (без альтернатив). Если на пиковой или делоадной неделе диапазон или состав упражнений отличается, факт-таблица повторяет именно эту неделю.

**Чего НЕ делать в Плане В:**

- Не создавать калибровочную неделю.
- Не вставлять блок чек-ина в week-N (это для онлайн-клиентов Плана А).
- Не выдумывать рабочие веса, если тренер не указал текущие 1RM или их нельзя надёжно оценить из 10РМ. Маркер `вес по факту` это явная инструкция тренеру.
- Не создавать блок `**Резюме прошлой недели:**` в офлайн-неделях, отчёт даёт тренер постфактум.
- Не добавлять в факт-таблицы лишние блоки, только заголовки дней и таблицы.

**Триггер прогрессии следующего мезо:** тренер присылает заполненные факт-таблицы из `fakt/` или короткий отчёт «Никита прошёл мезо 1, на жиме вышли на 75 кг x 6 при RIR 1, в приседе 105 x 8 при RIR 2, поясница не беспокоила, восстановление хорошее». На основе этого создаём `mesocycle-2/` с подпапками `program/` и `fakt/` и пятью неделями в каждой, по тем же правилам.

## МОЯ НАУЧНАЯ БАЗА (приоритетные источники)

Система опирается на следующие принципы — они являются эталоном для любых решений по программированию.

### Объёмные ориентиры (MEV / MAV / MRV)

**Источники:**
- Pelland, Remmert, Zourdos et al. (2024–2025)
- Bernárdez-Vázquez et al. (2022)

**Базовые значения** (средний уровень, дробные подходы/нед):

| Мышца              | MV  | MEV  | MAV    | MRV   |
|--------------------|-----|------|--------|-------|
| Грудные            | 4-6 | 6-9  | 10-20  | 22+   |
| Спина (широч.)     | 6-8 | 8-12 | 14-22  | 25-30 |
| Квадрицепсы        | 4-6 | 8-9  | 12-18  | 20    |
| Бицепс бедра       | 4   | 6    | 10-16  | 18    |
| Ягодичные          | 0-4 | 4-6  | 8-15   | 18+   |
| Ср./Задн. дельта   | 4-6 | 8-9  | 12-22  | 26+   |
| Трицепс (прямые)   | 4   | 6    | 10-14  | 18    |
| Бицепс (прямые)    | 4-5 | 6-8  | 10-14  | 18    |
| Икроножные         | 6   | 8    | 12-18  | 20+   |

**Корректировки MRV:**
- Новичок: × 0.70 | Продвинутый: × 1.20
- Сон <6ч: × 0.85 | Сон 6-7ч: × 0.90
- Стресс высокий: стартовать с нижней MEV
- Тяжёлая физ. работа: × 0.85

> 📖 Подробно: [[volume-landmarks/index]]

- Указывается длительность в минутах
- Указывается зона или ЧСС-диапазон

- Блок `**Альтернативы:**` для кардио не нужен

- Разделитель — ` • ` (символ U+2022 в окружении пробелов)
- Веса — через `/` без пробелов
- **Количество весов = количеству сетов** (4 сета → 4 веса, даже если все одинаковые: `60/60/60/60`)
- Десятичные — через точку: `22.5`
- Собственный вес — `0/0/0`
- Единица — ` кг` (с пробелом, в конце)

**Запрещено в week-N.md:**

- Таблицы для подходов
- Подзаголовки внутри дня (нет `### Разминка`)
- Markdown-форматирование внутри строки подхода
- Нумерация упражнений (`1.`, `2.`)
- Wiki-ссылки `[[...]]`
- Многострочные описания упражнения
- Колонки лога факта (Факт. вес / повт. / RIR) — фронтенд их генерит сам
- **Большая таблица сравнения** «Сводка изменений нед N → нед N+1» с колонками `план / факт / план / причина` по каждому упражнению. Используй короткое `**Резюме прошлой недели:**` с процентами + маркированный список `**Что меняем**` (см. ПРАВИЛО №3).

**Правило контекста недели (обязательно для каждой недели):**

Каждая неделя содержит обязательные информационные блоки сразу после `**Период:**`, до первого `## День`. Порядок строгий:

1. `**Резюме прошлой недели:**` (только нед 2+) — 2-3 предложения с процентами попадания и оценкой динамики, по алгоритму из ПРАВИЛА №3.
2. `**Рекомендация:**` — 1-2 предложения, фокус недели и целевой RIR.
3. `**Контекст недели:**` — 2-3 предложения простым языком без жаргона: что происходит на этой неделе и зачем, как это вписывается в общий план, чего ожидать от ощущений в теле (DOMS, лёгкость, усталость). Клиент не должен чувствовать себя потерянным.
4. `**Красные флаги:**` — 2-3 конкретных сигнала, при которых клиент пишет тренеру немедленно, не дожидаясь чек-ина. Формат: «Если X, напиши сразу.» Типичные: острая боль в суставах (не мышечная), головокружение, резкое падение сил на 2+ тренировках подряд.

Опциональные блоки той же зоны (если есть содержание):

5. `**По чек-ину:**` — 1-3 предложения, краткая реакция тренера на ТЕКСТОВЫЕ ответы клиента (сон, суставы, заметки), не на проценты подходов (для них есть Резюме).
6. `**Объём недели:**` — 1-2 предложения, где меняется количество подходов и почему.
7. `**Что меняем по сравнению с прошлой неделей:**` — маркированный список 3-7 пунктов, по одному на ключевое изменение, формат: `- Упражнение, было/стало, причина в 3-4 словах`.

`**Рекомендация дня:**` содержит 2-3 предложения: технические акценты на конкретные упражнения этого дня, явное указание времени отдыха между подходами в минутах, темп выполнения если важен. Не общие слова, а конкретика под этот день. После основного текста обязательно идут два подблока `**Разминка:**` и `**Заминка:**` со стандартной формулировкой по ПРАВИЛУ №4, без них рекомендация дня неполна.

**Альтернативы — обязательный блок после каждого упражнения:**

К каждому упражнению в `week-N.md` добавляется блок из 3 альтернатив на случай если у клиента нет возможности выполнить основное упражнение (нет тренажёра, дискомфорт, другая причина). Альтернативы подбираются по принципу проработки тех же мышечных групп. Формат строго:

```
**Альтернативы:**
- Название упражнения | [Видео](url) | N x M-K
- Название упражнения | [Видео](url) | N x M-K
- Название упражнения | [Видео](url) | N x M-K
```

Правила:
- Блок `**Альтернативы:**` идёт сразу после строки подходов, без пустой строки
- Названия берутся только из [[knowledge-base/exercises/exercise-library]]
- Ссылки берутся из библиотеки, если ссылки нет — строка без `[Видео](...)`
- Количество сетов и повторений в альтернативе соответствует основному упражнению

**Калибровочная неделя 1:**

- Веса всегда `0/0/0` (количество нулей = количеству сетов)
- В `**Рекомендация:**` обязательно слово «Калибровочная» или «подбираем веса»
- Блок `**Резюме прошлой недели:**` отсутствует (нет данных для резюме)
- Один блок «Алгоритм подбора веса» в конце файла

Полные правила: [[templates/README]] (раздел «ЖЁСТКИЙ ФОРМАТ файлов week-N»).

## 🚨 КРАСНЫЕ ФЛАГИ — реагируй немедленно

| Флаг | Действие |
|------|----------|
| Объём > MRV клиента без обоснования | Стоп. Пересчитать. Обосновать или снизить. |
| Нет делоада в мезоцикле | Обязательно вставить 5-ю неделю MV. |
| Тяжёлые тренировки при высоком стрессе + недосыпе | Снизить до MEV, увеличить RIR. |
| Упражнения с осевой нагрузкой при проблемах с поясницей | Заменить на безопасные альтернативы. |
| Падение рабочих весов 2+ недели подряд | Диагностика: объём, сон, питание, стресс. |
| Жалобы на боль в суставах (не мышечная) | Немедленно исключить нагрузку на сустав. |
